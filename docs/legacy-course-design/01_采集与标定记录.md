## 获取雷达 XYZ 与同一时刻图像对应点的实际流程

当前工程中已有 ADC 处理链，可以将每个雷达帧解析成检测表。处理后的字段包括 `Frame`、`X`、`Y`、`Z`、距离、速度和强度。

### 第一步 解析雷达 ADC

在 MATLAB 中运行：

```matlab
cd('E:\xinhaochuli')
export_radar_camera_pairs
```

脚本会分别处理两组 ADC，并输出：

```text
E:\xinhaochuli\radar_camera_pairs\20261014_163316\radar_detections_xyz.csv
E:\xinhaochuli\radar_camera_pairs\20261014_163615\radar_detections_xyz.csv
```

### 第二步 按帧映射配对图像

脚本读取对应的 `frame_mapping.json`，将雷达表中的 1\-based `Frame` 与 JSON 中的 0\-based `radar_frame_index` 对齐，补充：

- `CameraFrame0`：对应相机帧号；

- `MappingTimeDifference_ms`：雷达帧和相机帧的时间差；

- `X、Y、Z`：同一雷达帧中的目标坐标。

输出文件为：

```text
radar_camera_pairs.csv
```

并将对应的视频帧导出到 `paired_images` 文件夹。

### 第三步 获取图像中的对应位置

对于每个配对样本，需要在对应相机图像中确定同一个目标的像素位置 `u、v`。有两种方式：

|方式|做法|适用情况|
|---|---|---|
|人工点击|打开 `paired_images` 中的图像，在目标中心点击并记录 `u、v`|先做少量高质量标定样本|
|自动检测|使用棋盘格角点或目标检测算法得到中心点|图像目标清晰、形状稳定时|

最终对应表至少包含：

```text
radar_frame_index
video_frame_index
X, Y, Z
u, v
time_difference_ms
```

### 第四步 求解外参

使用多组对应数据求解：

```text
p_camera = R_radar_to_camera * p_radar + t_radar_to_camera
```

如果只有一个目标中心，深度和空间约束不足；建议让同一目标在不同距离、左右位置和高度产生至少 8～15 组对应点。目标位置需要在空间中分散，避免全部落在一条直线上。

### 当前可执行结论

- 相机内参已经有了；

- 雷达 XYZ 可以通过现有 ADC 处理链获得；

- 相机帧可以通过 `frame_mapping.json` 自动配对；

- 还需要补充图像像素点 `u、v` 和稳定的共同目标，才能求出外参 `R、t`。

## 6\. 当前情况与优化方向

### 6\.1 帧数差异的解释与处理

相机帧数与雷达帧数存在差异，是软同步流程下的正常现象。相机提前录像并在雷达完成后停止，因此会包含准备阶段和结束阶段的画面。

**优化方法：**

1. 读取会话文件和帧映射文件；

2. 统计每个雷达帧对应的相机帧和时间差；

3. 标记重复映射、空映射和时间差较大的对应；

4. 通过时间补偿参数减少整体偏移；

## 8\. 市面常用融合方案与本项目建议

|方案|基本做法|适用特点|本项目安排|
|---|---|---|---|
|数据级融合|将雷达目标投影到图像，再合并原始信息|信息完整，对标定精度要求高|标定稳定后进行实验|

|置信度加权|按图像检测质量和雷达目标稳定性分配权重|能发挥两种传感器互补优势|作为融合增强方法|

### 11\.4 重新采集的正式要求

下一次采集专门服务于雷达\-相机外参：

|要求|执行方式|
|---|---|
|固定设备|雷达和相机安装后保持相对位置不变，采集期间不移动|
|共同目标|使用相机能识别、雷达也能稳定反射的共同目标；不能只保证相机看得见|
|静态姿态|每个位置停留 1～2 秒，不边走边标定|
|空间覆盖|至少覆盖近、中、远距离，以及左、中、右位置和不同高度/倾角|
|样本数量|15～30 个不同姿态，避免所有点集中在一条直线或一个小区域|
|时间同步|保留视频、ADC、`session.json`、`frame_mapping.json` 和串口日志|
|参数记录|记录相机帧率、分辨率、时间补偿、棋盘格尺寸和设备相对位置|
|试采验收|先做短采集，确认雷达帧、视频和映射文件都生成后再正式采集|

如果使用棋盘格，建议增加雷达可检测的平面目标或反射结构，并在每个姿态中选择雷达点云的稳定中心，而不是随意点击某一个跳动的候选点。

### 11\.5 重新采集后的执行顺序

1. 先完成驱动、JTAG、UART、相机和采集 GUI 的连接验收；

2. 做一次短试采，检查文件数量、帧号、时间戳和视频完整性；

3. 按静态多姿态要求正式采集；

4. 在 MATLAB 中运行 `export_radar_camera_pairs`；

5. 用 `annotate_extrinsic_pairs` 生成共同目标对应表；

6. 用 `estimate_extrinsic_from_pairs` 计算 R、t 和重投影误差；

7. 若误差较大，先剔除错误对应点并检查目标稳定性，不直接使用异常外参；

8. 通过独立姿态验证投影效果后，再进入雷达\-相机融合算法。
