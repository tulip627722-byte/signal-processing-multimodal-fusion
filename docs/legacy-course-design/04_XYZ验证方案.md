# 04 · 相机-雷达标定 XYZ 验证方案（下一步）

> 状态：内参、外参均已固定。本文档固化下一步的验证思路与帧数不一致的处理方式。

## 1. 为什么必须验证 XYZ

静态外参拟合的像素残差很小（6/6 内点，mean ≈ 1.6 px），**但存在深度退化隐患**：

- 6 个标定对应点在雷达系里几乎挤在同一位置（X≈-0.24, Y≈1.99, Z≈0.30 m）；
- 补偿到相机系后深度 **Z_cam ≈ 7.4 m**（quick 版甚至 27.5 m），而目标实际距离只有 ~2 m；
- 单点邻域内重投影误差可以很小，但沿视线方向的尺度不可观——**像素误差小 ≠ XYZ 正确**。

结论：必须用全场点云叠加做独立验证，不能只看标定残差。

## 2. 验证思路（点云重合，直接看是否出物品）

1. 固定参数：内参 `K`、`D`（第二轮 2 阶畸变定稿）+ 外参 `R`、`t`（`results/extrinsic_calibration_static.mat`）。
2. 对某个会话，取每个雷达帧的**全部检测点**（`radar_camera_pairs/<会话>/radar_camera_pairs.csv`，含 X/Y/Z/强度/TrackID）。
3. 用 `Pc = R*Pr + t` 变换到相机系，再经 `K`、`D` 投影成像素 `(u, v)`。
4. 把投影点叠加到**配对的相机帧图像**上（按距离/强度上色），逐帧输出叠加图和 MP4。
5. 直接肉眼判读：点云是否落在真实目标（角反/标定板/强反射体）上。

## 3. 帧数不一致不是问题（499 vs 799）

- 雷达帧数 ≠ 相机帧数是软同步采集的常态：相机先启动、后停止，多出的帧是准备/收尾画面。
- `savedata/Sync/<会话>_frame_mapping.json` 的 `rows` 已给出逐帧 1:1 配对：`radar_frame_index` → `video_frame_index`，且导出表 `radar_camera_pairs.csv` 里每行检测都带 `CameraFrame0` 列。
- 验证脚本按 `CameraFrame0` 取图即可；没有雷达帧对应的相机帧直接跳过。
- 参考量级：雷达 499 帧 ↔ 相机 760~799 帧，499 个雷达帧全部有唯一配对，无重复复用。

## 4. 判读标准与分支

| 叠加表现 | 结论 | 动作 |
|---|---|---|
| 各距离/位置点云都落在目标上 | XYZ 可信 | 进入融合应用 |
| 仅标定点附近准，远/近/边缘系统性偏移 | 确认深度退化 | 补多姿态（近中远/左右/高低，15–30 组）重采重标 |
| 点云整体旋转/平移错位 | R 或 t 有误 | 检查坐标系约定（雷达 +X 右 / +Y 前 / +Z 上）与对应点 |
| 点云上下/左右翻转 | 轴方向约定错 | 修正 R 的轴映射 |
