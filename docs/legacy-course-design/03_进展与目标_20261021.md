## 1. 总目标

## 3. 当前问题（一句话）

**卡在坐标对齐的对应点质量，不在雷达点云算法，也不在「有没有做雷达实时/硬件同步开发」。**

| 怀疑项 | 是否主因 | 说明 |
|--------|----------|------|
| ADC / RD / CFAR / XYZ 写错 | 否 | 与老师输出一致 |
| 5 帧打框算法 | 否 | 老师验证 PASS；外参用 detection 表 |
| 相机内参 / 投影模型 | 否 | ~0.12 px；外参脚本含畸变 |
| 外参 LM 拟合实现 | 基本否 | 坏对应点上正确求解器也会失败 |
| 无硬件时间戳 / 非实时 | 次要 | 动态会放大误差；静态可先做外参 |
| **人工对应点 / 标定姿态** | **是** | 弱点、Z 乱跳、姿态/目标不够稳 |

## 4. 下一步怎么做

1. **固定安装**：雷达与相机相对位姿不再移动。  
2. **静止共同目标**：棋盘格 + 强反射体；每个姿态静止 1–2 秒；采 15–30 个分散姿态（近中远、左右、高低）。  
3. 跑 `export_radar_camera_pairs.m`。  
4. 标注时：图像点板中心（或固定角）；雷达只点 **高强度、Z 稳定** 的检测，尽量同一 TrackID；弱杂波右键跳过。  
5. 跑 `estimate_extrinsic_from_pairs.m`；仅 `calibrationValid=true`（或残差达课设可用水平）才用于融合。  
6. 硬件时间戳有固件后再升级同步；不必等实时开发完成才做外参。

人工点不准时的兜底：先近距静态强反射验证残差能否下降；用回波复核脚本确认真目标；后续可加 TrackID 约束或 RANSAC 剔点。
