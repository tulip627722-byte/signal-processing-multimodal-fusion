# 使用与安全注意事项

## 数据与隐私

- 不提交 `radar_adc.mat`、RGB/深度图、PLY 点云、生成的 `*_res.mat` 或压缩数据包。
- 彩色图可能包含车牌、人脸和场地信息，上传前必须单独检查。
- `meta.json` 可能包含设备序列号和本机端口信息，示例数据需要脱敏。

## 坐标与单位

- 所有坐标和距离统一使用米。
- 雷达角度使用度。
- 相机坐标为 `X 右 / Y 下 / Z 前`。
- 雷达坐标为 `X 右 / Y 前 / Z 上`。
- `cameraOriginInRadarM` 表示相机原点在雷达坐标系中的位置，不是目标距离。

## 补偿符号

配置中保存的是测量偏差，应用规则为：

```text
corrected = measured - bias
```

例如雷达方位系统性偏右 `3.2 deg`，则从测量方位中减去 `3.2 deg`。不要同时修改雷达角度和机械外参旋转，否则会重复补偿。

## Astra Pro 室外限制

- 室外红外干扰会造成深度缺失和远距离噪声。
- 深度内参来自设备视场估计时，不应作为厘米级真值。
- 室外验证应优先使用卷尺距离、棋盘 RGB 中心和雷达原始距离谱。
- RGB 与深度流没有精确联合标定时，RGB 投影只能作为弱验证。

## 时间同步

- 雷达时间使用物理帧首包/末包接收窗中点。
- 相机帧按 `manifest.csv` 的单调时钟匹配。
- 如果彩色流时间明显超过雷达记录时长，不能把同编号文件视为严格同步真值。

## 参数变更

- 修改正式外参、雷达补偿或 FFT 波形参数后必须强制重算结果。
- 每个结果的 `metaOut` 必须保存实际使用的参数和来源。
- 不允许将状态为 `FAIL` 或 `applicable=false` 的候选外参用于正式计算。
