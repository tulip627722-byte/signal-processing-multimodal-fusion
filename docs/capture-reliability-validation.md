# 采集程序优化检验

## 本次目标

解决采集端在不同电脑上容易因网卡地址、串口编号变化而无法启动，以及雷达未启动或采集中断流时只能依靠人工发现和重启的问题。

## 已实现能力

- 开始采集前检查本机是否存在雷达固件固定目标地址 `192.168.220.10`；缺失时列出当前 IPv4，并明确提示给雷达有线网卡添加静态地址。
- 自动枚举全部串口，优先 USB 串口特征，但不再只凭名称认定设备；以收到雷达 UDP ADC 包作为启动成功的最终依据。
- 首次启动无回包时自动轮询候选串口并重发 Start。
- 正常采集后超过 2 秒没有新雷达包，自动执行 Pause/Start、重开串口或切换候选串口。
- GUI 状态栏显示雷达健康状态与自动恢复次数，`meta.json` 记录 `serial.recoveryAttempts`。

## 2026-11-12 自动检验

在 Windows、无真实雷达参与的环境执行：

```powershell
cd capture\app
.\build.ps1
.\bin\Acquire.exe --self-test --duration 2
.\bin\Acquire.exe --ui-smoke-test
```

结果：

- C# .NET Framework 4.0 x64 编译通过。
- 无硬件自检通过，`SELF-TEST PASSED`。
- 真实 UDP 回环链路收到 6464 个逻辑包，生成并回读 `radar_adc.mat`。
- `manifest.csv` 时间单调，彩色、深度、点云、雷达四路文件与元数据一致。
- GUI 冒烟测试正常打开并退出，退出码为 0。
- 自检中首个 UDP 包被正确识别为“雷达启动/恢复成功”。
- 相机启动增加实际首帧验收：所选彩色/深度流必须在 3 秒内返回帧，进入记录后还要确认图片已落盘；否则停止任务并在 GUI 弹窗，不允许静默生成只有雷达的结果。

由于仓库不提交原始采集数据、MAT、PNG、PLY 和二进制文件，自检产物保留在本地忽略目录，不上传 GitHub。

## XYZ 验证边界

已验证的坐标定义：

```text
相机坐标：X 右 / Y 下 / Z 前
雷达坐标：X 右 / Y 前 / Z 上

Xr = Xc
Yr = Zc
Zr = -Yc
```

自动自检覆盖：

1. 已知 2 m 合成深度平面反投影到相机 XYZ。
2. 图像中心、视场边界和物理宽高检查。
3. 相机坐标转换到雷达坐标。
4. 二进制 PLY 写入后回读首点坐标与顶点数量。
5. 16-bit 深度 PNG 编解码往返一致。

因此 XYZ 轴方向、单位和程序转换链路已经验证。正式外参 `R/t` 的真实数据留出验证见 `docs/extrinsics`。2026-11-05 雷达角度偏差候选仍属于实验参数，其中 3 m 组约 `0.16 m`，尚未满足所有组均不超过 `0.15 m` 的合并门限。

## 真机验收建议

换电脑或更新硬件后执行一次 10–20 秒真机采集，并确认：

- 雷达状态变为“运行正常”，而不是持续“自动检测中”。
- 拔插或暂停雷达后状态变为“断流，自动重启中”，恢复后回到“运行正常”。
- `meta.json` 中雷达包数大于 0，`serial.port` 为实际控制串口。
- 排除停止时尾帧后，雷达丢包率符合现场网络要求。
- 使用已知位置目标再次检查真实 XYZ 和外参误差，避免把通信自检等同于几何精度验收。

若 Astra 报 `Failed to set USB interface`，先确认没有旧版 `Acquire.exe`、OrbbecViewer 或 NiViewer 占用设备；关闭后拔掉相机 USB 等 5 秒，再插到电脑 USB 3.x 接口。该错误发生在 Windows/Orbbec 驱动占用层，不是雷达故障。
